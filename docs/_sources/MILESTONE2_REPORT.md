# Milestone 2 report (added without changes to original Milestone 1)

The new `milestone2.ipynb` is a live, executable report notebook. It computes all statistics, comparisons and plots **at notebook execution/book-build time** from:

- `report_data/milestone2_summary.json`
- `report_data/milestone2_status.csv`

These files are generated by the new parser: `python -m src.milestone2.cli --output data --report ../report_repo` from the `source_repo` folder. They must not be confused with original Mile 1 report data; a partial run is clearly labeled as such. The original `milestone1.ipynb`, `_toc.yml`, `_config.yml`, `index.md` and README are preserved.

## Build the cumulative Jupyter Book

From `report_repo` (Python 3.11+):

```sh
python -m pip install -r requirements.txt
python build_combined.py
```

The build creates `_build_combined/index.html` and the Milestone 1 / Milestone 2 pages by **copying the original book into a temporary directory**, adding Mile 2 to the temporary `_toc.yml`, and running Jupyter Book there. It does not alter the original Mile 1 report files or replace the existing `_build/` folder. This staging design is intentional to satisfy a strict requirement to keep Milestone 1 source and report architecture unchanged.

The final benchmark must be rerun on a Google Colab CPU-only instance and the resulting measured files synced, as required by the course statement.

## GitHub Pages (opt-in, original workflow untouched)

The new `.github/workflows/pages-mile1andmile2.yml` can be started from **Actions → Build and deploy Mile 1 + Mile 2 Jupyter Book → Run workflow**. It publishes the staged `_build_combined/` output. The original `.github/workflows/pages.yml` still runs on pushes and builds the original Mile 1 site; after pushing source changes, invoke the combined workflow manually to publish both pages.
